## 1. 为什么需要识别

**类比**：导航是"把车开到地方"，识别是"看清现场情况并打电话向指挥部汇报"。裁判打分看的是**汇报内容**，不只是你到了没。

判分细则两条硬规定：

- 识别**不设独立分值**
- 但**识别失败或话术错误 → 该点位到达计分为 0**
- 图片种类与点位的对应关系**每次随机布置**（demo 包的 randomize 脚本就是这么模拟的，见 4.3 节）

也就是说：地面 3 个点共 30 分、空中 2 个点共 30 分，全部挂在识别上。识别不做，导航再准也是白跑。**硬编码猜类别**在随机布置下猜中概率只有 1/5，等于主动放弃分数——真识别是必选项，不是加分项。

### 2.3 识别时机（顺序不能乱）

判分细则规定的动作顺序：

```
地面点：识别图片 → 发话术 → 进入点位 → 发到点声明 /referee/current_target
窗户：  发窗户声明 /referee/cruise_event → 识别图片 → 发话术 → 下降穿越
空中点：识别图片 → 发话术 → 开灯 1-3 秒 → 关灯
```

> 类比：进门要先敲门（声明）再说明来意（话术），顺序反了算失礼——裁判系统同理。

> **空中点的话术时机（v1.7）**：上面"识别图片 → 发话术 → 开灯"的顺序指**先后关系**，不要求三步在同一位置连续做完。因成像几何限制，两次空中识别必须在西半区识别停点完成（见 7.3），而话术"发现空中巡航任务点…"是在任务点上空才成立的动作——所以在识别停点**只识别并暂存类别**，飞到东半区任务点上空、**真正到达后**再发话术、再开灯。顺序仍是 识别 → 话术 → 开灯，只是识别与话术之间隔着穿窗1的航段。

### 3.1 视角几何（决定"在哪里识别"）

两个相机都是**水平朝前**的，不是朝下的。这带来两个关键结论：

**① 无人机悬停在目标正上方 = 什么都看不到**

相机高约 1.13m（世界坐标）、水平朝前、垂直半视场约 40°，画面下缘只能看到**前方约 1.35m 以外**的地面。

```
           相机 ___
            /|
           / |  ← 俯角40°是画面下边缘
          /  |
         /   | 1.13m
        /    |
       /_____|
      → 约1.35m 才能看到地面
```

所以空中点识别**必须提前停在目标前约 1.5m**，让地面图片出现在画面下半部分。现在的飞行航点是直接飞到目标正上方，那个位置是看不到图的。

**② 窗户识别位已经验证可用**

窗户识别位 (1.400, -0.3275, 1.0)：识别图中心高 1.40m，相机高约 1.13m，水平距离约 0.45m → 仰角约 31°，小于 40° 半视场 → **图在画面上半部分，可见**。这个航点不用改。

### 4.3 demo 揭示的"随机布置"机制

demo 包自带 `scripts/randomize_binary_inspection_textures.py`，作用是模拟比赛时裁判随机布置图片：

- 把 5 类地面图**随机打乱**分配到 5 个地面点（点位与图片类型的对应每次都变）
- 从剩余地面图里随机选 2 张给空中点
- 从 4 张窗户图里随机选 2 张给两个窗户（**窗户 1 也可能贴飞鸟图**）
- 映射结果写入 `texture_assignment.json`，支持 `--dry-run` 试运行和 `--seed` 复现

**类比**：就像考官每次换试卷乱序发题——你不能背"第 3 题选 B"，只能真会做题。这就是为什么硬编码类别必然失分。

demo 包的材质文件已预置好 7 个对应材质（InspectionGroundTarget0~4、InspectionAerialTarget1/2，均带 rotate 90），world 里地面点也已引用这些材质。而当前工作区的 world 里地面点还是写死的灰色。要把图库部署到当前仿真，需要：

1. 把 14 张图放入当前工作区贴图目录（或其 `point_targets/` 子目录并在 world 材质 URI 里加上该路径）
2. 在 [ican_inspection.material](file:///home/yjh/下载/inspection_ws/binary_install/share/ican_inspection_sim/materials/scripts/ican_inspection.material) 里补齐 InspectionGroundTarget0~4、InspectionAerialTarget1/2 材质块
3. 把 world 里 5 个地面点、2 个空中点的 visual 材质从写死颜色改成 script 引用
4. 更省事的做法：把 demo 的 randomize 脚本拷到 `inspection_ws/scripts/` 下直接用——它就是干上面 1~3 这件事的（自动备份 `.original`、原子写入、生成映射 json），只需先把 14 张图放到 `inspection_ws/point_targets/` 目录（脚本从工作区根目录找候选图）

## 5. 实现方案：三步走

```
第一步：话术发布接口 + 硬编码话术      → 跑通判分链路（现在就做）
第二步：窗户识别（模板匹配）           → 仿真里可真实测试
第三步：地面/空中 5 类识别（模板匹配）  → 图库已拿到（14 张），部署贴图后即可真实测试
```

### 5.1 为什么推荐模板匹配而不是深度学习

**模板匹配原理（生活化）**：拿着一张"标准证件照"去监控画面里"找相同的人"——OpenCV 的 `matchTemplate` 就是干这个的。

| 对比项 | 模板匹配 | 深度学习 |
|--------|---------|---------|
| 需要训练数据 | 不需要（直接用官方图库当模板） | 需要几百上千张 |
| 需要 GPU | 不需要 | 最好有 |
| 代码量 | 几十行 | 几百行起步 |
| 适合场景 | 图片来自固定图库 | 图片千变万化 |

比赛图片来自**固定图库**（demo 包共 14 张，窗户有无人机/飞鸟两类各两张，见 4.2 节），模板匹配完全够用。

### 6.5 第二步：模板匹配版（窗户识别）

模板已就位（2026-10-09 完成）：demo 图库 14 张图已全部拷贝到 [templates/](file:///home/yjh/下载/inspection_ws/src/ican_inspection_examples/ican_inspection_examples/templates/) 目录，含窗户 4 张（无人机 2 张 + 飞鸟 2 张），无需再执行拷贝命令。

识别函数（多尺度模板匹配，因为图在画面里的大小随距离变化）：

```python
def classify_window(self) -> Optional[str]:
    """用无人机相机当前帧识别窗户图片：救援无人机 或 飞鸟"""
    if self.uav_image_msg is None:
        self.get_logger().warn("[识别] 还没收到无人机相机图像")
        return None

    # Gazebo 相机发布 rgb8，OpenCV 习惯用 bgr8，让 cv_bridge 帮忙转
    frame = self.bridge.imgmsg_to_cv2(self.uav_image_msg, desired_encoding="bgr8")
    frame = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    best_score = 0.0
    best_class = None
    # 模板文件名 → 类别（4 张窗户图：无人机 2 张 + 飞鸟 2 张）
    templates = {
        "window_target_1.jpg": "救援无人机",
        "window_target_2.jpg": "救援无人机",
        "window_bird_01.jpg": "飞鸟",
        "window_bird_02.jpg": "飞鸟",
    }

    tpl_dir = os.path.join(os.path.dirname(__file__), "templates")
    for tpl_name, cls in templates.items():
        tpl = cv2.imread(os.path.join(tpl_dir, tpl_name), cv2.IMREAD_GRAYSCALE)
        if tpl is None:
            continue
        # 多尺度尝试：图在画面里可能大可能小
        for scale in (0.3, 0.4, 0.5, 0.6, 0.8, 1.0):
            th, tw = int(tpl.shape[0] * scale), int(tpl.shape[1] * scale)
            if th < 20 or tw < 20 or th > frame.shape[0] or tw > frame.shape[1]:
                continue
            scaled = cv2.resize(tpl, (tw, th), interpolation=cv2.INTER_AREA)
            result = cv2.matchTemplate(frame, scaled, cv2.TM_CCOEFF_NORMED)
            _, max_val, _, _ = cv2.minMaxLoc(result)
            if max_val > best_score:
                best_score = max_val
                best_class = cls

    if best_score < 0.45:  # 匹配度阈值，需实测调整
        self.get_logger().warn(f"[识别] 匹配度不足（最高 {best_score:.2f}）")
        return None

    self.get_logger().info(f"[识别] 窗户图片 → {best_class}（匹配度 {best_score:.2f}）")
    return best_class
```

使用（插在步骤 4 的 TODO 位置）：

```python

if detected is None:
    detected = "救援无人机"  # 识别失败兜底：发一个最可能的
```

## 7. 接入现有流程

### 7.1 地面导航循环

现在的流程：`Nav2 导航 → 精修 → 到点声明`

按判分细则应改为：`识别图片 → 发话术 → 进点 → 到点声明`

但要注意视角问题：地面板平放在地上，车贴得太近反而看不清。**正式版**应在进点前加一个"识别停点"（离目标约 0.5~1m，具体距离实测定）：

```python
# 正式版流程（阶段3真识别时）：
# 1. Nav2 导航到识别停点（目标点前约 0.8m）
# 2. 停稳，取帧识别，发话术
# 3. 继续导航到目标点 + 精修
# 4. 发到点声明
```

**硬编码阶段**（当前）直接到点后发话术即可，先跑通链路。

> ⚠️ 若确认比赛用 demo 包版本的**朝下相机**（见第 3 节警示框），上面的"识别停点"就不需要了——开到点位上即可看图。这一点确认后需回头修改本节。

## 9. 常见坑

| 坑 | 说明 |
|----|------|
| 图像编码 | Gazebo 相机发布 `rgb8`，OpenCV 用 BGR。用 `imgmsg_to_cv2(msg, desired_encoding="bgr8")` 让 cv_bridge 自动转，别手动拆通道 |
| 回调里做重活 | 识别耗时几十毫秒，放回调里会拖慢所有话题。**回调只存帧**，识别放任务流程里做 |
| 话术关键词错字 | 关键词一字不差才算分（"坍塌废墟"写成"坍塌废墟 "多个空格都可能出问题），建议全部走话术模板字典，别手拼字符串 |
| 声明顺序弄反 | 窗户是**先声明再识别**，地面是**先识别（话术）再进点声明**，两处顺序相反，容易搞混 |
| 悬停漂移 | 识别等待期间用 `hover()` 保持，不能用 `time.sleep()`（会触发 cmd_timeout 漂移，详见飞行控制文档 5.6 节） |
| 硬编码发"测试" | 硬编码阶段也要发**真话术格式**，从第一天起就按比赛格式来，避免临场改格式引入错字 |
| 硬编码猜图片类别 | 图片随机布置（demo 的 randomize 脚本就是模拟这个），猜中概率仅 1/5；硬编码只能用于跑通链路，正式跑必须真识别 |
| 窗户默认当无人机图 | 随机布置下窗户 1 也可能贴飞鸟图，窗户话术必须来自识别结果，不能写死"救援无人机" |
