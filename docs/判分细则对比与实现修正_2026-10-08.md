## 一、最大速度限制：0.5 m/s（⚠️ 当前违规）

### 细则原文（通用约定第4条）

> 各任务移动速度不得超过 0.5m/s（暂定）：裁判系统检测到移动速度超限时，**锁定该任务后续计分**（已获分数保留）。

### 我们当前的问题

| 文件 | 参数 | 当前值 | 是否合规 |
|------|------|-------|---------|
| `nav2_ground_params.yaml` | `max_vel_x` | **0.65** | ❌ 超限 |
| `nav2_ground_params.yaml` | `max_vel_y` | **0.65** | ❌ 超限 |
| `nav2_ground_params.yaml` | `max_speed_xy` | **0.75** | ❌ 超限 |
| `minimal_user_node.py` | `fly_to.max_xy_speed` | **0.3** | ✅ 合规 |
| `minimal_user_node.py` | `refine_ground_pose.max_xy_speed` | **0.35** | ✅ 合规 |
| `minimal_user_node.py` | `takeoff` 等开环演示 | 0.25 | ✅ 合规 |

### 修正方案

**Nav2 速度参数必须降到 0.5 以下**：

```yaml
# nav2_ground_params.yaml
FollowPath:
  max_vel_x: 0.45        # 从 0.65 降到 0.45（留 0.05 余量）
  max_vel_y: 0.45        # 同上
  max_speed_xy: 0.50     # 从 0.75 降到 0.50
  max_vel_theta: 0.90    # 角速度不限制（裁判检测的是线速度）
```

> **之前文档错误认知**：[Nav2地面导航实现框架.md](file:///home/yjh/下载/inspection_ws/docs/Nav2地面导航实现框架.md) 第7.2节说"降速会增加完成时间，得不偿失，速度参数建议保持原值"——**这是错的**！裁判系统有 0.5 m/s 硬限制，超限直接锁分。

## 二、地面点位：随机抽签 3 个（⚠️ 当前硬编码 6 个）

### 细则原文（2.1 任务流程第1条）

> 裁判系统启动时从 5 个地面点位中**随机抽取 3 个点位**（经 `/referee/ground_tasks` 发布，如 `ground_2、ground_4、ground_1`），主程序按抽签顺序导航。

### 我们当前的问题

```python
# minimal_user_node.py 当前代码
self.ground_task_waypoints = {
    "ground_0": (1.125, -1.350, 0.0),
    "ground_1": (0.000, -1.350, 0.0),
    "ground_2": (0.000, -2.700, 0.0),
    "ground_3": (1.125, -1.925, math.pi/2),
    "ground_4": (1.125, -0.775, math.pi/2),
    "ground_5": (0.000, 0.000, 0.0),   # ← ground_5 是指挥中心，不在 5 个点位里
}

# run() 方法里遍历所有 6 个点
for name, point in self.ground_task_waypoints.items():
    ...
```

**问题**：
1. 硬编码遍历全部 6 个点，实际应该只去裁判抽签的 3 个
2. `ground_5` 是指挥中心（起降点），不是地面巡检点位
3. 没有订阅 `/referee/ground_tasks` 获取抽签结果
4. 没有按抽签顺序导航

### 修正方案

```python
# 1. 订阅裁判系统的抽签结果
self.create_subscription(
    String, "/referee/ground_tasks",
    self.on_ground_tasks, 10
)

# 2. 收到抽签后，按顺序导航
def on_ground_tasks(self, msg):
    """裁判发布 3 个随机点位，如 "ground_2,ground_4,ground_1" """
    self.selected_points = msg.data.split(",")

# 3. 导航时只去抽签的 3 个点
for name in self.selected_points:
    point = self.all_ground_waypoints[name]
    self.send_ground_nav_goal(point)
```

### 我们当前的问题

2. 起飞前确保地面导航完全结束
3. 降落后切换回地面模式时，先发 `/uav/cmd_vel` 全零再停

### 11.1 新增裁判系统话题发布者

```python
# __init__ 中新增
from std_msgs.msg import String

self.referee_target_pub = self.create_publisher(String, "/referee/current_target", 10)
self.referee_event_pub = self.create_publisher(String, "/referee/cruise_event", 10)
self.inspection_detections_pub = self.create_publisher(String, "/inspection/detections", 10)

# 订阅裁判抽签
self.selected_ground_points = None
self.create_subscription(String, "/referee/ground_tasks", self.on_ground_tasks, 10)

def on_ground_tasks(self, msg):
    """裁判发布随机抽签的 3 个点位"""
    self.selected_ground_points = msg.data.split(",")
    self.get_logger().info(f"裁判抽签点位：{self.selected_ground_points}")

def publish_arrival(self, point_name):
    """到点后发布声明"""
    msg = String()
    msg.data = point_name  # 如 "ground_2"
    self.referee_target_pub.publish(msg)

def publish_detection(self, detection_text):
    """发布识别话术"""
    msg = String()
    msg.data = detection_text  # 如 "发现坍塌废墟，地面巡航任务点确认..."
    self.inspection_detections_pub.publish(msg)

def publish_window_decl(self, window_name):
    """穿越窗户前发布声明"""
    msg = String()
    msg.data = window_name  # 如 "window_1"
    self.referee_event_pub.publish(msg)

def publish_landing(self):
    """降落后发布声明"""
    msg = String()
    msg.data = "landing_marker"
    self.referee_event_pub.publish(msg)
```

## 十二、之前文档的错误修正

### 错误1：速度参数建议（Nav2地面导航实现框架.md 第7.2节）

**原文**：
> 速度参数建议保持原值。比赛评分规则：同分情况下，用时少的队伍排名靠前。降速会增加完成时间，得不偿失。

**修正**：
> **必须降速！** 裁判系统硬限制 0.5 m/s，超限直接锁分。Nav2 `max_vel_x` 必须从 0.65 降到 0.45，`max_speed_xy` 从 0.75 降到 0.50。

### 错误2：航点遍历方式（Nav2地面导航实现框架.md 第3节）

**原文**：
> 遍历 5 个巡检点。`for name, point in self.ground_task_waypoints.items():`

**修正**：
> 不能遍历全部点位。裁判系统从 5 个地面点位中随机抽取 3 个（经 `/referee/ground_tasks` 发布），必须订阅该话题获取抽签结果，按抽签顺序导航。

### 错误3：缺少裁判系统交互（所有文档）

**原文**：文档只讲了 Nav2 导航和飞行控制，没有提到裁判系统话题。

**修正**：
> 必须实现裁判系统交互：到点声明、窗户声明、降落声明、识别话术上报。否则即使到达点位也不会得分（"识别失败时，即使到达点位，到达点位有效计分为 0"）。
