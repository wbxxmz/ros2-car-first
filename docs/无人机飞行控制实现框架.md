# 无人机飞行控制实现框架

## 1. 为什么飞行要自己写

地面阶段有 **Nav2** 帮你算路径、避障、控制方向，你只需要告诉它"去哪里"。

但空中阶段，仿真**只给了底层速度接口** `/uav/cmd_vel`，没有"飞行版的 Nav2"。你必须自己写控制器，让无人机飞到指定点。

### 地面 vs 飞行

| | 地面 | 飞行 |
|--|------|------|
| 谁帮你算 | Nav2 | 没有，自己写 |
| 接口 | `navigate_to_pose` action（给坐标） | `/uav/cmd_vel`（给速度） |
| 你要做的 | 发坐标点 | 不断算速度、发速度 |

### 类比

- **地面** = 你用高德地图导航，输入目的地，它自动带你走
- **飞行** = 你蒙眼开车，没有导航，只能自己摸方向、踩油门、打方向盘

## 2. 飞行的核心思路：闭环控制

### 2.1 开环 vs 闭环

**开环**（模板原来的方式）：
```
踩油门 2 秒 → 松油门
```
不管车走了多远、有没有撞墙。就像你闭眼踩油门，时间到就松，开到哪算哪。

**闭环**（我们要写的）：
```
不断重复：
  1. 看 /uav/odom，知道我现在在哪
  2. 算目标点 - 我现在位置 = 还差多远
  3. 速度 = 距离差 × 系数（离得远跑得快，离得近跑得慢）
  4. 发 /uav/cmd_vel
  5. 距离够近了，停
```

> 类比：蒙眼走到椅子旁边——伸手摸（看 odom），远就大步走，近就小步挪，摸到了停。

### 2.2 为什么用闭环

| 问题 | 开环 | 闭环 |
|------|------|------|
| 怎么知道到没到 | 不知道，靠猜 | 看 odom 实时位置 |
| 到了能停吗 | 不能，时间到才停 | 能，到了立刻停 |
| 撞墙了怎么办 | 继续撞 | 能看到墙，调整方向 |
| 精度 | 很差 | 较好 |

### 2.3 P 控制（比例控制）

我们用最简单的 **P 控制**：

```
输出速度 = 误差 × 比例系数 Kp
```

**误差** = 目标位置 - 当前位置

举例（假设 Kp = 0.8）：

| 距离目标还有多远 | 计算 | 输出速度 |
|-----------------|------|---------|
| 1.0 米 | 1.0 × 0.8 | 0.8 m/s（快跑） |
| 0.5 米 | 0.5 × 0.8 | 0.4 m/s（中速） |
| 0.1 米 | 0.1 × 0.8 | 0.08 m/s（慢慢挪） |
| 0.0 米 | 0.0 × 0.8 | 0.0 m/s（停） |

**效果**：
- 离得远 → 速度大 → 跑得快
- 离得近 → 速度小 → 跑得慢
- 到了 → 速度 0 → 停

> 就像你走过去拿杯子：离得远大步走，快到了放慢手速，拿到了停。

### 2.4 限幅

P 控制在误差很大时，算出来的速度也会很大。比如距离 5 米，Kp=0.8，速度就是 4 m/s，太快了会失控。

所以要限制最大速度：

```python
cmd.linear.x = max(-max_speed, min(max_speed, kp * error))
```

拆解：
- `kp * error`：P 控制算出的速度
- `min(max_speed, ...)`：不超过最大速度
- `max(-max_speed, ...)`：不低于负的最大速度（倒退也有限制）

> 就像汽车油门踩到底也不会无限加速，有个最高速度限制。

## 3. 关键接口详解

### 3.1 /uav/cmd_vel（发速度指令）

**消息类型**：`geometry_msgs/msg/Twist`

Twist 消息结构：
```
Twist
├── linear（线速度）
│   ├── x  → 前后
│   ├── y  → 左右
│   └── z  → 上下
└── angular（角速度）
    ├── x  → 绕 x 轴转（翻滚，不用）
    ├── y  → 绕 y 轴转（俯仰，不用）
    └── z  → 绕 z 轴转（偏航，转向用）
```

**每个字段的含义**：

| 字段 | 正值 | 负值 | 单位 |
|------|------|------|------|
| `linear.x` | 向前飞 | 向后飞 | m/s |
| `linear.y` | 向左飞 | 向右飞 | m/s |
| `linear.z` | 向上升 | 向下降 | m/s |
| `angular.z` | 向左转 | 向右转 | rad/s |

**⚠️ 超级重要**：`linear.x` 是"机器人的前方"，**不是世界的 x 轴方向**！

举个例子：
- 如果机器人朝东（yaw=0°），`linear.x=0.3` 就是往东飞
- 如果机器人朝北（yaw=90°），`linear.x=0.3` 就是往北飞
- 所以 `linear.x` 的方向取决于机器人当前的朝向

这就是为什么后面要做**坐标系转换**。

### 3.2 /uav/odom（看当前位置）

**消息类型**：`nav_msgs/msg/Odometry`

Odometry 消息结构（我们只关心 pose 部分）：
```
Odometry
├── header
│   └── stamp → 时间戳
├── child_frame_id → 通常是 "base_link"
└── pose
    └── pose
        ├── position（位置）
        │   ├── x → 世界坐标 x
        │   ├── y → 世界坐标 y
        │   └── z → 世界坐标 z（高度）
        └── orientation（朝向，四元数）
            ├── x
            ├── y
            ├── z
            └── w
```

**注意**：这里的 position 是**世界坐标系**下的位置，orientation 是**四元数**格式的朝向。

### 3.3 /uav/laser_fire（激光开关）

**消息类型**：`std_msgs/msg/Bool`

```
Bool
└── data → true（开激光）或 false（关激光）
```

## 4. 坐标系转换详解

### 4.1 两种坐标系

**世界坐标系（map / world）**：
- 原点固定在地图的某个点
- x 轴永远朝东，y 轴永远朝北，z 轴永远朝上
- 不管机器人怎么转，世界坐标系都不变

**机体坐标系（base_link）**：
- 原点在机器人中心
- x 轴永远是机器人的前方
- y 轴永远是机器人的左方
- z 轴永远是机器人的上方
- 机器人一转，机体坐标系也跟着转

### 4.2 为什么必须转换

`/uav/cmd_vel.linear.x` 控制的是"机器人前方"的速度，也就是**机体坐标系**的 x 方向。

但我们从 `/uav/odom` 拿到的目标误差是**世界坐标系**下的。

如果不转换直接用：

假设机器人朝北（yaw=90°），目标在机器人东边（世界 x 正方向）：
- 世界误差：err_x = 1.0, err_y = 0.0
- 如果你直接 `linear.x = kp * err_x = 0.8`
- 机器人会往北飞（因为它朝北，前方是北）
- 但目标在东边！→ 飞错方向了

所以必须把世界误差转成机体坐标。

### 4.3 转换公式推导

绕 z 轴旋转角度 θ 的旋转矩阵：
```
[cosθ  -sinθ]
[sinθ   cosθ]
```

机器人当前朝向是 `cyaw`（世界坐标到机体坐标的旋转角）。

要把世界坐标的误差 `(err_x, err_y)` 转成机体坐标 `(body_x, body_y)`，需要反向旋转 `-cyaw`：

```python
body_x =  err_x * cos(-cyaw) - err_y * sin(-cyaw)
body_y =  err_x * sin(-cyaw) + err_y * cos(-cyaw)
```

### 4.4 举例验证

假设：
- 机器人当前位置 (0, 0, 1)
- 机器人朝北，cyaw = 90° = π/2
- 目标点在 (1, 0, 1)（东边）

计算：
```
err_x = 1 - 0 = 1.0
err_y = 0 - 0 = 0.0
cyaw = π/2

cos(-π/2) = 0
sin(-π/2) = -1

body_x = 1.0 * 0 - 0.0 * (-1) = 0
body_y = 1.0 * (-1) + 0.0 * 0 = -1.0
```

结果：`body_x = 0`（不往前），`body_y = -1.0`（往右）

这正确！因为机器人朝北，目标在东边，也就是机器人的右边，所以应该往右飞。

> 如果不转换，直接 `linear.x = err_x = 1.0`，机器人会往北飞，完全错了。

## 5. 代码实现（逐行详解）

### 5.1 yaw_from_quaternion：从四元数算偏航角

```python
def yaw_from_quaternion(qx, qy, qz, qw) -> float:
    siny_cosp = 2.0 * (qw * qz + qx * qy)
    cosy_cosp = 1.0 - 2.0 * (qy * qy + qz * qz)
    return math.atan2(siny_cosp, cosy_cosp)
```

**作用**：`/uav/odom` 里的朝向是四元数 `(qx, qy, qz, qw)`，要转成角度 `yaw`（弧度）才能用。

| 行 | 说明 |
|----|------|
| `siny_cosp = 2.0 * (qw * qz + qx * qy)` | 四元数转欧拉角的标准公式，算 sin(yaw) × cos(pitch) |
| `cosy_cosp = 1.0 - 2.0 * (qy * qy + qz * qz)` | 算 cos(yaw) × cos(pitch) |
| `return math.atan2(siny_cosp, cosy_cosp)` | 用 atan2 算出 yaw 角（弧度，范围 -π 到 π） |

> 这是 ROS 官方推荐的四元数转 yaw 公式。你不用理解推导，只要知道"四元数进来，角度出去"就行。

**举例**：
- 四元数 (0, 0, 0, 1) → yaw = 0°（朝东）
- 四元数 (0, 0, 0.707, 0.707) → yaw = 90°（朝北）
- 四元数 (0, 0, 1, 0) → yaw = 180°（朝西）

### 5.2 get_uav_pose：获取当前位置和朝向

```python
def get_uav_pose(self) -> Optional[Tuple[float, float, float, float]]:
    if self.uav_odom is None:
        return None
    p = self.uav_odom.pose.pose.position
    o = self.uav_odom.pose.pose.orientation
    yaw = yaw_from_quaternion(o.x, o.y, o.z, o.w)
    return p.x, p.y, p.z, yaw
```

**作用**：从订阅到的 `/uav/odom` 数据里，取出当前位置和朝向。

**逐行**：

| 行 | 代码 | 说明 |
|----|------|------|
| 1 | `if self.uav_odom is None:` | 检查有没有收到 odom 数据 |
| 2 | `return None` | 还没收到，返回空（调用方要处理） |
| 3 | `p = self.uav_odom.pose.pose.position` | 取出位置对象 p，有 p.x, p.y, p.z |
| 4 | `o = self.uav_odom.pose.pose.orientation` | 取出朝对象 o，有 o.x, o.y, o.z, o.w（四元数） |
| 5 | `yaw = yaw_from_quaternion(o.x, o.y, o.z, o.w)` | 四元数转偏航角 |
| 6 | `return p.x, p.y, p.z, yaw` | 返回 (x, y, z, yaw) |

**返回值**：`(x, y, z, yaw)` 或 `None`

> `self.uav_odom` 是在 `__init__` 里订阅 `/uav/odom` 时注册的回调 `on_uav_odom` 里赋值的。odom 数据一到，回调就更新 `self.uav_odom`。

### 5.3 fly_to：核心飞行控制方法

这是整个飞行控制的心脏，详细解释每一部分。

#### 完整代码

```python
def fly_to(self, x, y, z, yaw=0.0,
           pos_tol=0.15, yaw_tol=0.15,
           max_xy_speed=0.3, max_z_speed=0.25,
           max_yaw_speed=0.5, timeout_sec=30.0) -> bool:
    deadline = time.monotonic() + timeout_sec
    kp_xy = 0.8
    kp_z = 0.6
    kp_yaw = 1.0

    while rclpy.ok() and time.monotonic() < deadline:
        rclpy.spin_once(self, timeout_sec=0.0)
        pose = self.get_uav_pose()
        if pose is None:
            time.sleep(0.05)
            continue

        cx, cy, cz, cyaw = pose
        err_x = x - cx
        err_y = y - cy
        err_z = z - cz
        err_yaw = yaw - cyaw
        while err_yaw > math.pi:
            err_yaw -= 2.0 * math.pi
        while err_yaw < -math.pi:
            err_yaw += 2.0 * math.pi

        if (abs(err_x) < pos_tol and abs(err_y) < pos_tol
                and abs(err_z) < pos_tol and abs(err_yaw) < yaw_tol):
            self.uav_cmd_vel_pub.publish(Twist())
            return True

        body_x = err_x * math.cos(-cyaw) - err_y * math.sin(-cyaw)
        body_y = err_x * math.sin(-cyaw) + err_y * math.cos(-cyaw)

        cmd = Twist()
        cmd.linear.x = max(-max_xy_speed, min(max_xy_speed, kp_xy * body_x))
        cmd.linear.y = max(-max_xy_speed, min(max_xy_speed, kp_xy * body_y))
        cmd.linear.z = max(-max_z_speed, min(max_z_speed, kp_z * err_z))
        cmd.angular.z = max(-max_yaw_speed, min(max_yaw_speed, kp_yaw * err_yaw))
        self.uav_cmd_vel_pub.publish(cmd)
        time.sleep(0.05)

    self.uav_cmd_vel_pub.publish(Twist())
    return False
```

#### 参数详解

| 参数 | 默认值 | 类型 | 含义 |
|------|--------|------|------|
| `x` | 必填 | float | 目标世界坐标 x（米） |
| `y` | 必填 | float | 目标世界坐标 y（米） |
| `z` | 必填 | float | 目标世界坐标 z（高度，米） |
| `yaw` | 0.0 | float | 目标朝向（弧度） |
| `pos_tol` | 0.15 | float | 位置到位容差（米），误差小于这个算到位 |
| `yaw_tol` | 0.15 | float | 角度到位容差（弧度），约 8.6° |
| `max_xy_speed` | 0.3 | float | 水平最大速度（m/s） |
| `max_z_speed` | 0.25 | float | 垂直最大速度（m/s） |
| `max_yaw_speed` | 0.5 | float | 最大转向速度（rad/s），约 28.6°/s |
| `timeout_sec` | 30.0 | float | 超时时间（秒），超过返回失败 |

#### 逐段讲解

**第 1 段：初始化**

```python
deadline = time.monotonic() + timeout_sec
kp_xy = 0.8
kp_z = 0.6
kp_yaw = 1.0
```

| 代码 | 说明 |
|------|------|
| `deadline = ...` | 计算超时的时间点（当前时间 + 超时秒数） |
| `kp_xy = 0.8` | 水平方向（前后左右）的 P 控制系数 |
| `kp_z = 0.6` | 垂直方向（升降）的 P 控制系数 |
| `kp_yaw = 1.0` | 转向的 P 控制系数 |

> `time.monotonic()` 返回从某个固定时间点到现在的秒数，不受系统时间调整影响，适合用来计时。

**第 2 段：控制循环**

```python
while rclpy.ok() and time.monotonic() < deadline:
```

| 条件 | 说明 |
|------|------|
| `rclpy.ok()` | ROS 2 还在运行（没被 Ctrl+C） |
| `time.monotonic() < deadline` | 还没超时 |

两个条件都满足才继续循环，否则跳出。

**第 3 段：处理回调 + 获取位置**

```python
rclpy.spin_once(self, timeout_sec=0.0)
pose = self.get_uav_pose()
if pose is None:
    time.sleep(0.05)
    continue
```

| 代码 | 说明 |
|------|------|
| `rclpy.spin_once(...)` | 让 ROS 处理一次待处理的回调（更新 odom 数据） |
| `pose = self.get_uav_pose()` | 拿当前位置 |
| `if pose is None` | 还没收到 odom 数据 |
| `time.sleep(0.05); continue` | 等 50ms 再试 |

> `spin_once` 很重要！如果不调它，odom 回调不会执行，`self.uav_odom` 就不会更新，你拿到的永远是旧数据。

**第 4 段：计算误差**

```python
cx, cy, cz, cyaw = pose
err_x = x - cx
err_y = y - cy
err_z = z - cz
err_yaw = yaw - cyaw
while err_yaw > math.pi:
    err_yaw -= 2.0 * math.pi
while err_yaw < -math.pi:
    err_yaw += 2.0 * math.pi
```

| 代码 | 说明 |
|------|------|
| `cx, cy, cz, cyaw = pose` | 解构当前位置 (x, y, z) 和朝向 yaw |
| `err_x = x - cx` | x 方向误差 = 目标 x - 当前 x |
| `err_y = y - cy` | y 方向误差 |
| `err_z = z - cz` | z 方向误差（高度差） |
| `err_yaw = yaw - cyaw` | 角度误差 = 目标朝向 - 当前朝向 |
| `while err_yaw > pi: err_yaw -= 2π` | 把角度误差归一化到 [-π, π] |
| `while err_yaw < -pi: err_yaw += 2π` | 同上 |

**角度归一化的重要性**：

假设目标朝向是 -179°，当前朝向是 179°：
- 不算归一化：err_yaw = -179 - 179 = -358° → 机器人会转将近一整圈
- 归一化后：-358° + 360° = 2° → 机器人只转 2° 就到了

归一化让机器人永远走最短的转向路径。

**第 5 段：判断是否到位**

```python
if (abs(err_x) < pos_tol and abs(err_y) < pos_tol
        and abs(err_z) < pos_tol and abs(err_yaw) < yaw_tol):
    self.uav_cmd_vel_pub.publish(Twist())
    return True
```

| 代码 | 说明 |
|------|------|
| `abs(err_x) < pos_tol` | x 方向误差小于容差 |
| `abs(err_y) < pos_tol` | y 方向误差小于容差 |
| `abs(err_z) < pos_tol` | z 方向误差小于容差 |
| `abs(err_yaw) < yaw_tol` | 角度误差小于容差 |
| 四个都满足 | 到位了！ |
| `publish(Twist())` | 发零速度，让无人机停住 |
| `return True` | 返回成功 |

> 四个条件必须同时满足才算到位。`abs()` 是取绝对值，因为误差可能是正的也可能是负的。

**第 6 段：坐标转换**

```python
body_x = err_x * math.cos(-cyaw) - err_y * math.sin(-cyaw)
body_y = err_x * math.sin(-cyaw) + err_y * math.cos(-cyaw)
```

把世界坐标的误差 `(err_x, err_y)` 转成机体坐标 `(body_x, body_y)`。

详细解释见第 4 节。

**第 7 段：计算速度指令**

```python
cmd = Twist()
cmd.linear.x = max(-max_xy_speed, min(max_xy_speed, kp_xy * body_x))
cmd.linear.y = max(-max_xy_speed, min(max_xy_speed, kp_xy * body_y))
cmd.linear.z = max(-max_z_speed, min(max_z_speed, kp_z * err_z))
cmd.angular.z = max(-max_yaw_speed, min(max_yaw_speed, kp_yaw * err_yaw))
```

| 代码 | 说明 |
|------|------|
| `cmd = Twist()` | 创建一个空的速度消息 |
| `cmd.linear.x = ...` | 前后速度 = P控制(body_x)，限幅在 ±max_xy_speed |
| `cmd.linear.y = ...` | 左右速度 = P控制(body_y)，限幅在 ±max_xy_speed |
| `cmd.linear.z = ...` | 升降速度 = P控制(err_z)，限幅在 ±max_z_speed |
| `cmd.angular.z = ...` | 转向速度 = P控制(err_yaw)，限幅在 ±max_yaw_speed |

**注意**：
- `linear.x` 和 `linear.y` 用的是 `body_x` 和 `body_y`（机体坐标）
- `linear.z` 用的是 `err_z`（高度不需要转换，因为 z 轴在世界和机体里都是向上）
- `angular.z` 用的是 `err_yaw`（角度误差）

**第 8 段：发送指令 + 延时**

```python
self.uav_cmd_vel_pub.publish(cmd)
time.sleep(0.05)
```

| 代码 | 说明 |
|------|------|
| `self.uav_cmd_vel_pub.publish(cmd)` | 把速度指令发到 `/uav/cmd_vel` |
| `time.sleep(0.05)` | 等 50ms，控制频率约 20Hz |

> 为什么要 sleep？如果不延时，循环会跑得非常快，CPU 占用 100%，而且发速度的频率太高反而会出问题。20Hz 是比较合适的控制频率。

**第 9 段：超时处理**

```python
self.uav_cmd_vel_pub.publish(Twist())
return False
```

循环退出（超时了），发零速度停住，返回失败。

### 5.4 takeoff：起飞

```python
def takeoff(self, height=1.0) -> bool:
    pose = self.get_uav_pose()
    if pose is None:
        self.get_logger().error("无法获取无人机位置，起飞失败。")
        return False
    _, _, _, cyaw = pose
    self.get_logger().info(f"起飞到高度 {height:.2f}m")
    return self.fly_to(pose[0], pose[1], height, cyaw)
```

**原理**：起飞 = 飞到"当前 x, y，高度=height"的位置。

| 行 | 代码 | 说明 |
|----|------|------|
| 1 | `pose = self.get_uav_pose()` | 获取当前位置 |
| 2-4 | `if pose is None: ... return False` | 拿不到位置就失败 |
| 5 | `_, _, _, cyaw = pose` | 取出当前朝向 cyaw（x, y, z 用 _ 忽略） |
| 6 | `self.get_logger().info(...)` | 打印日志 |
| 7 | `return self.fly_to(pose[0], pose[1], height, cyaw)` | 飞到 (当前x, 当前y, height)，朝向不变 |

> 起飞只改变 z（高度），x、y 保持当前位置，yaw 保持当前朝向。

### 5.5 land：降落

```python
def land(self) -> bool:
    pose = self.get_uav_pose()
    if pose is None:
        return False
    self.get_logger().info("降落中...")
    return self.fly_to(pose[0], pose[1], 0.05, pose[3])
```

**原理**：降落 = 飞到"当前 x, y，高度=0.05"的位置。

| 行 | 代码 | 说明 |
|----|------|------|
| 1 | `pose = self.get_uav_pose()` | 获取当前位置 |
| 2-3 | `if pose is None: return False` | 拿不到位置就失败 |
| 4 | `self.get_logger().info(...)` | 打印日志 |
| 5 | `return self.fly_to(pose[0], pose[1], 0.05, pose[3])` | 飞到 (当前x, 当前y, 0.05m) |

> 降到 0.05m 而不是 0，是为了避免撞到地面。`pose[3]` 是当前朝向 yaw，保持朝向不变。

### 5.6 hover：悬停（非常重要）

```python
def hover(self, seconds: float) -> None:
    """悬停指定秒数，期间持续发零速度，避免 cmd_timeout 超时。"""
    deadline = time.monotonic() + seconds
    zero = Twist()
    while rclpy.ok() and time.monotonic() < deadline:
        rclpy.spin_once(self, timeout_sec=0.0)
        self.uav_cmd_vel_pub.publish(zero)
        time.sleep(0.05)   # 20Hz
```

**作用**：在悬停期间持续以 20Hz 发零速度指令，保证 `/uav/cmd_vel` 不断流，**避免触发插件的 `cmd_timeout`**。

| 行 | 代码 | 说明 |
|----|------|------|
| 1 | `deadline = time.monotonic() + seconds` | 计算悬停结束时间 |
| 2 | `zero = Twist()` | 预创建零速度消息（避免循环里重复构造） |
| 3 | `while rclpy.ok() and time.monotonic() < deadline:` | 还没到时间就继续 |
| 4 | `rclpy.spin_once(...)` | 处理回调（更新 odom） |
| 5 | `self.uav_cmd_vel_pub.publish(zero)` | 发零速度，告诉插件"我要悬停" |
| 6 | `time.sleep(0.05)` | 20Hz 频率，每 50ms 发一次 |

#### 为什么不能用 time.sleep？

仿真插件 `ican_gazebo_uav_simple_move` 配置了 `<cmd_timeout>0.5</cmd_timeout>`（见 [inspection_task1.world](file:///home/yjh/下载/inspection_ws/binary_install/share/ican_inspection_sim/worlds/inspection_task1.world#L435)）：

- 如果 **0.5 秒内没收到新的 `/uav/cmd_vel` 指令**，插件进入超时状态
- `time.sleep(1.0)` 等 1 秒不发指令 → 超过 0.5 秒 cmd_timeout → 行为不可控（可能漂移或掉高度）
- `hover()` 每 50ms 发一次零速度 → cmd 不断流 → 插件保持悬停

> 类比：simple_move 插件像"喂饭机器人"，每 0.5 秒得喂一次指令（哪怕零速度也算喂了）。`time.sleep` 就是 1 秒不喂饭，机器人进入"没收到指令"的超时状态；`hover` 是每 50ms 喂一次"零速度"，机器人知道你还在控制它，保持悬停。

#### fly_to 返回后为什么也要 hover？

`fly_to` 到位时只发**一次** `Twist()`，之后函数返回。如果调用方紧接着 `time.sleep`，就回到了上面"断流"的问题。所以悬停期间一律用 `hover()`，不能用 `time.sleep()`。

## 7. 一次完整的 fly_to 执行过程示例

假设：
- 当前位置：(0, 0, 0.1)，朝向 0°（朝东）
- 目标位置：(1, 0, 1.0)，朝向 0°
- Kp_xy = 0.8, Kp_z = 0.6, max_xy = 0.3, max_z = 0.25

### 第一次循环

```
1. 获取位置：cx=0, cy=0, cz=0.1, cyaw=0
2. 算误差：err_x=1-0=1.0, err_y=0, err_z=1.0-0.1=0.9, err_yaw=0
3. 没到位（误差都大于 0.15）
4. 坐标转换：cyaw=0，cos(0)=1, sin(0)=0
   body_x = 1.0*1 - 0*0 = 1.0
   body_y = 1.0*0 + 0*1 = 0
5. 算速度：
   linear.x = min(0.3, 0.8*1.0) = 0.3（限幅了）
   linear.y = 0
   linear.z = min(0.25, 0.6*0.9) = 0.25（限幅了）
6. 发速度：x=0.3, z=0.25（往前并上升）
```

### 第十次循环（假设已经飞了 0.5 米）

```
1. 获取位置：cx=0.5, cy=0, cz=0.6, cyaw=0
2. 算误差：err_x=0.5, err_y=0, err_z=0.4, err_yaw=0
3. 没到位
4. 坐标转换：body_x=0.5, body_y=0
5. 算速度：
   linear.x = 0.8*0.5 = 0.4 → 限幅到 0.3
   linear.z = 0.6*0.4 = 0.24
6. 发速度：x=0.3, z=0.24
```

### 接近目标时

```
1. 获取位置：cx=0.92, cy=0, cz=0.92, cyaw=0
2. 算误差：err_x=0.08, err_y=0, err_z=0.08, err_yaw=0
3. 到位了！（都小于 0.15）
4. 发零速度，return True
```

## 9. 飞行安全设计

比赛规则对飞行有硬性要求，违反会直接扣分或锁分。本节列出所有安全约束，调参和写代码时都要遵守。

### 9.1 速度限制（≤0.5m/s）

| 参数 | 安全上限 | 当前默认 | 是否合规 |
|------|---------|----------|---------|
| `max_xy_speed`（水平） | 0.5 m/s | 0.3 m/s | ✅ 有余量 |
| `max_z_speed`（升降） | 0.5 m/s | 0.25 m/s | ✅ 有余量 |
| `max_yaw_speed`（转向） | 无明确限制 | 0.5 rad/s | — |

**注意事项**：
- 速度限制是**合成速度**，即 `sqrt(linear.x² + linear.y² + linear.z²) ≤ 0.5`
- 当前默认值 0.3/0.25 已经满足，**不要为了快把 max_speed 调到 0.5 以上**
- 如果要提速，建议 `max_xy_speed=0.4, max_z_speed=0.3`，合成速度仍 < 0.5

> 类比：高速公路限速 120，你开 100 已经很快了，没必要顶到 120 还要超。

### 9.2 高度要求（≥80cm）

| 阶段 | 高度要求 | 原因 |
|------|---------|------|
| 巡航飞行 | z ≥ 0.8m | 避开地面障碍（墙 0.4m、窗户底框 0.4m） |
| 穿越窗户 | z ∈ [0.4, 1.15]m | 窗户空隙区间 |
| 识别窗户 | z = 1.0m | 与识别图同高（识别图在 z=1.40m，略低于它便于识别） |
| 降落 | z → 0.05m | 接地 |

> 飞行阶段统一用 z=1.0m 巡航，穿越时降到 z=0.7m，这是最安全的组合。

### 9.3 窗户穿越区间（z ∈ [0.40, 1.15]m）

详见第 6.3 节。**穿越高度选 z=0.7m**，理由：
- 正好在区间正中间（0.40 + 1.15）/ 2 = 0.775，取整 0.7
- 上下各留 30cm 安全余量
- P 控制有 ±15cm 的到位容差，即使误差大也仍在区间内

### 9.4 场地边界（不能飞出去）

详见第 6.4 节。安全飞行边界（留 20cm 余量）：

| 方向 | 墙坐标 | 安全飞行边界 |
|------|--------|------------|
| 北 | y = 0.675 | y ≤ 0.475 |
| 南 | y = -3.375 | y ≥ -3.175 |
| 西 | x = -0.800 | x ≥ -0.600 |
| 东 | x = 4.250 | x ≤ 4.050 |

> 当前所有目标点都在安全边界内，不需要额外处理。但调参时如果出现振荡冲出去，要检查坐标是否超出。

### 9.5 超时保护（防止卡死）

`fly_to` 默认 `timeout_sec=30.0`，每个航点最多飞 30 秒。如果超时：
- 函数返回 False
- 调用方 warn 后继续下一步（不 return 终止整个流程）

> 类比：每个航点给你 30 秒，到不了就跳过，别在一个地方卡死。

| `kp_z` | 0.6 | 0.3 ~ 0.4 | 升降更温和 |
| `max_xy_speed` | 0.3 | 0.15 ~ 0.2 | 限制最大速度 |
| `max_z_speed` | 0.25 | 0.15 ~ 0.2 | 限制升降速度 |

> 振荡 = 无人机到了目标点附近来回晃，停不下来。原因是 Kp 太大，速度减得不够快，冲过头了又往回冲。

### 10.3 到位判断

| 参数 | 当前值 | 调大效果 | 调小效果 |
|------|--------|---------|---------|
| `pos_tol` | 0.15 | 更容易判定到位（精度降低） | 更难判定到位（精度提高） |
| `yaw_tol` | 0.15 | 朝向要求更宽松 | 朝向要求更严格 |

> 如果无人机到位后一直微调停不下来，把 `pos_tol` 调大到 0.25 或 0.3。

### 10.4 调参顺序建议

1. **先调 Kp**：从 0.8 开始，观察振荡情况，振荡就减小
2. **再调 max_speed**：根据需要的速度调整
3. **最后调 tol**：根据到位精度调整

## 12. 常见问题排查

### Q1：无人机起飞后漂移，停不下来

**原因**：`/uav/odom` 的位置有噪声，P 控制会一直微调，而且到位判定太严格。

**解决**：
- 把 `pos_tol` 从 0.15 调大到 0.25 或 0.3
- 到位后 `publish(Twist())` 确保停住

### Q2：无人机飞不到目标点，超时

**原因**：
- 速度太小，飞太慢
- 坐标超出场地范围
- 有障碍物挡住（但我们没做避障）

**解决**：
- 增大 `max_xy_speed`（0.3 → 0.5）
- 增大 `timeout_sec`（30 → 60）
- 检查目标坐标是否在场地内

### Q3：无人机方向乱飞

**原因**：坐标转换没做好，或者 odom 的 yaw 不对。

**解决**：
- 检查 `yaw_from_quaternion` 是否正确
- 确认 `body_x/body_y` 转换公式
- 打印 `cyaw` 看看朝向对不对

### Q4：起飞后直接掉下来

**原因**：`linear.z` 速度太小，升力不够。

**解决**：
- 增大 `kp_z`（0.6 → 1.0）
- 增大 `max_z_speed`（0.25 → 0.4）

### Q5：到位后还在小幅移动

**原因**：P 控制的固有特性，误差不为 0 就一直有速度输出。

**解决**：
- 增大 `pos_tol`，让到位判定更宽松
- 到位后立刻 `publish(Twist())` 清零

## 13. 与识别阶段衔接

飞行到位后，可以加入目标识别：

```python
if self.fly_to(window_x, window_y, window_z, 0.0):
    # 到位了，开始识别
    self.get_logger().info("开始目标识别")
    if self.detect_target():
        self.get_logger().info("检测到目标，发射激光")
        self.set_laser(True)   # 开激光
        self.hover(1.0)       # 悬停 1 秒（不能用 sleep，见 5.6 节）
        self.set_laser(False)  # 关激光
    else:
        self.get_logger().warn("未检测到目标")
```

1. 订阅 `/uav/camera/image` 话题
2. 用 OpenCV 处理图像（颜色/形状/模板匹配）
3. 判断是否有目标
