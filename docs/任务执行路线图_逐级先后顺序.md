## 总览：5 个阶段，按顺序推进

```
阶段1（P0）参数修正        → 满足裁判速度限制
阶段2（P0）裁判系统对接     → 能收到抽签、能发声明

阶段5（P1）降落收尾        → 降落声明，完成比赛
```

每个阶段都是下一阶段的前提。不要跳着做。

## 阶段 3：地面图片识别（P1）

### 做什么

在每个地面点位识别 5 类图片之一，发布话术到 `/inspection/detections`。

### 5 类图片与话术

| 图片种类 | 必须包含的关键词 | 完整话术 |
|---------|----------------|---------|
| 坍塌废墟 | `发现坍塌废墟` | 发现坍塌废墟，地面巡航任务点确认，将巡航信息发送回指挥中心。 |
| 滑坡塌方 | `发现滑坡塌方` | 发现滑坡塌方，地面巡航任务点确认，将巡航信息发送回指挥中心。 |
| 被困人员 | `发现被困人员` | 发现被困人员，地面巡航任务点确认，将巡航信息发送回指挥中心。 |
| 受损车辆 | `发现受损车辆` | 发现受损车辆，地面巡航任务点确认，将巡航信息发送回指挥中心。 |
| 救援营地 | `发现救援营地` | 发现救援营地，地面巡航任务点确认，将巡航信息发送回指挥中心。 |

### 实现步骤

```
1. 订阅 /camera/image（地面前向相机）
2. 用 OpenCV 或深度学习识别图片种类
3. 发布对应话术到 /inspection/detections
```

### 在 run() 中的位置

```python
for name in self.selected_ground_points:
    point = self.all_ground_waypoints[name]
    # ← 在导航前识别图片
    image = self.get_ground_image()
    detected_class = self.classify_image(image)  # 返回 "坍塌废墟" 等
    self.publish_detection(f"发现{detected_class}，地面巡航任务点确认，将巡航信息发送回指挥中心。")
    # 导航到点位
    if self.send_ground_nav_goal(point):
        self.publish_arrival(name)
```

### 注意

- **识别不设独立分值**，但识别失败时即使到达点位，到达点位有效计分为 0
- **识别话术中必须包含裁判匹配关键词**，否则判定不正确
- 没有图像识别能力时，可以临时硬编码话术来跑通流程

## 阶段 4：飞行窗户穿越（P1）

### 做什么

地面导航完成后，起飞飞行：穿越 2 个窗户 + 识别 2 个空中点。

### 任务流程

```
起飞（高度 ≥ 1m，满足 ≥80cm 要求）
  ↓
窗户1：
  1. 发窗户声明 /referee/cruise_event → "window_1"
  2. 识别窗户图片（救援无人机 或 飞鸟）
  3. 发话术 /inspection/detections
  4. 下降穿越窗户
  ↓
空中点1：
  1. 识别图片（5 类之一）
  2. 发话术 /inspection/detections
  3. 开灯 /uav/laser_fire → true
  4. 保持 1-3 秒
  5. 关灯 /uav/laser_fire → false
  ↓
空中点2：
  同空中点1
  ↓
窗户2：
  1. 发窗户声明 → "window_2"
  2. 识别 + 穿越同窗户1
```

### 关键规则

- **飞行高度不得低于 80cm**（灯光定位时）
- **灯光照射 1-3 秒**，不能乱晃
- **撞到外墙或窗框 → 裁判锁定后续计分**（已获分数保留）
- 地面导航期间 `/uav/cmd_vel` 速度不能非零（否则地面点不计分）

### 在 run() 中的位置

```python
# 地面导航完成后
self.takeoff(height=1.0)
time.sleep(0.5)  # 稳定

# 窗户1
self.publish_window_decl("window_1")
# TODO 识别窗户图片
self.fly_to(window1_x, window1_y, 0.5, 0.0)  # 下降穿越
time.sleep(1.0)
self.fly_to(window1_x, window1_y, 1.0, 0.0)  # 升回来

# 空中点1
# TODO 识别图片
self.fly_to(air1_x, air1_y, 1.0)
time.sleep(0.5)  # 悬停稳定
self.laser_pub.publish(Bool(data=True))
time.sleep(2.0)
self.laser_pub.publish(Bool(data=False))

# 空中点2（同上）

# 窗户2
self.publish_window_decl("window_2")
# 同窗户1
```

### 注意

- 穿越窗户后要升回来，不能一直在低空飞
- 灯光开关前要先悬停稳定 0.5 秒，避免"灯光乱晃"被判零分

## 阶段 5：降落收尾（P1）

### 做什么

飞回指挥中心上空，降落，发降落声明。

### 任务流程

```
1. 飞回指挥中心上空 (0, 0, 1.0)
2. 下降到 0.05m
3. 发降落声明 /referee/cruise_event → "landing_marker"
```

### 在 run() 中的位置

```python
# 飞回指挥中心
self.fly_to(0.0, 0.0, 1.0)
# 降落
self.land()
# 降落声明
self.publish_landing()
```

### 注意

- 降落声明必须在**降落后**发布
- 降落区域是指挥中心（起降点），半径 0.30m 内且高度不高于 0.30m

## 常见问题

**Q：阶段 2 能不能跳过识别直接发声明？**
A：可以临时跳过识别（硬编码话术），但比赛时识别失败即使到点也不计分。建议尽早实现识别。

**Q：阶段 4 的窗户坐标是什么？**
A：窗户 1 ≈ (1.925, -0.328)，窗户 2 ≈ (1.925, -2.373)，空中点 1 ≈ (3.080, -0.320)，空中点 2 ≈ (3.080, -1.355)。详见 [Nav2地面导航实现框架.md](file:///home/yjh/下载/inspection_ws/docs/Nav2地面导航实现框架.md) 第5节。

**Q：地面导航期间不小心发了 /uav/cmd_vel 怎么办？**
A：地面点不计分。确保地面阶段只发 `/cmd_vel`，飞行阶段才发 `/uav/cmd_vel`，切换时先发全零停止对方通道。

**Q：速度超限会怎样？**
A：裁判系统检测到移动速度超 0.5 m/s 时，**锁定该任务后续计分**（已获分数保留）。所以 Nav2 速度必须降到 0.5 以下。
