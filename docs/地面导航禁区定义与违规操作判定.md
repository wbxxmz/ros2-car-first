### 2.4 场地可用区域（物理上可到达的范围）

```
可用区域 = 外墙以内 - 窗框地面投影
        = { x ∈ [-0.775, 4.225], y ∈ [-3.350, 0.650] }
          - { x ∈ [1.845, 2.005], y ∈ [-1.0275, 0.3725] }
```

**简化理解**：场地在 x=1.845 处被窗框"切"了两刀，形成三条通道：

- 中间窗框走廊：x ∈ [1.845, 2.005]，被两个窗户各占一段 y 范围，中间是可通行的走廊

```

    × 地面行驶进入（含两窗缝隙 y∈[-1.6725,-1.0275]）
    × 从窗户上方飞越（z > 1.15 越过竖条）
    × 在竖条内悬停/爬升（非穿越动作）

【规则禁区 B：东半区（地面阶段）】
  地面导航阶段（起飞前）机器人必须全程在西半区：x < 1.845
  东半区 x > 2.005 只允许飞行阶段（空中任务）进入

【规则禁区 C：地面阶段全程禁止起飞】
  地面 3 点巡航期间不得发任何非零 /uav/cmd_vel；起飞时机只能是
  "完成全部地面任务 → 返回指挥中心(0,0) → 从指挥中心起飞"（官网任务二原文）
```

### 3.2 实时 costmap

- **obstacle_layer**：使用 `/scan`（激光雷达）实时标记障碍物
- **max_obstacle_height**：1.20m（地面层窗框底框高 0.40m，侧柱从 z=0 开始，激光雷达可以扫到）
- **inflation_radius**：0.24m（自动膨胀障碍物，让小车离墙至少 0.24m）
- **footprint**：0.44m×0.36m（矩形，碰撞检测按此尺寸）

### 3.3 静态地图分段实测（v1.1 新增）⚠️ 发现规则漏洞

对竖条 x∈[1.845, 2.005] 按 y 逐段检查静态地图像素（0=墙，254=自由）：

| y 段 | 对应结构 | 自由占比 | 结论 |
|------|---------|---------|------|
| y∈[-1.0275, -0.8275] | w1 侧S柱 | 50% | 部分阻挡 |
| y∈[-0.8275, 0.1725] | w1 底框 | 0% | 墙，不可过 |
| y∈[0.1725, 0.3725] | w1 侧N柱 | 0% | 墙，不可过 |
| **y∈[-1.6725, -1.0275]** | **两窗之间缝隙** | **80%** | **⚠️ 自由空间，Nav2 可规划穿越！** |
| y∈[-1.8725, -1.6725] | w2 侧N柱 | 0% | 墙，不可过 |
| y∈[-2.8725, -1.8725] | w2 底框 | 0% | 墙，不可过 |

**关键结论**：两窗缝隙（y≈-1.67~-1.03，宽 0.645m）在 Nav2 眼里是**可通行通道**。机器人 footprint 宽 0.36m + 单侧膨胀 0.24m 共需 0.84m > 0.645m，膨胀层大概率仍会封住它，但这**依赖 inflation 配置而非显式规则**——一旦膨胀参数调整、局部 costmap 清除异常或收到东半区目标点，Nav2 就可能规划穿缝隙。代码层面**没有任何 x 边界硬守卫**。

### 5.3 当前代码静态排查结论（为什么会起飞）

对当前 `minimal_user_node.py` 与 Gazebo 模型插件的排查：

| 排查项 | 结论 |
|--------|------|
| `/uav/cmd_vel` 发布点 | 仅 `fly_to()`、`hover()`、`stop_uav()` 三处；地面循环不调用这些函数 |
| 地面阶段执行路径 | `send_ground_nav_goal` + `refine_ground_pose`，只发 `/cmd_vel`（轮子） |
| Gazebo 模型插件 | 麦克纳姆轮插件订阅 `/cmd_vel`；飞控插件 `libican_gazebo_uav_simple_move.so` 只订阅 `/uav/cmd_vel`，两者独立，地面指令不会产生升力 |
| **静态结论** | **按当前代码逻辑，地面阶段不应自发起飞** |

可能的真实诱因（需运行时监测最终定位）：
- **a)** 运行的是旧版本安装副本（历史版本空中识别停点曾为 x=1.85m，恰在竖条禁区内，后已西移至 1.30m；若改动后未 `colcon build`，会跑旧代码）；
- **b)** 地面任务结束后在最后一个地面点直接 `takeoff()`（当前代码确实如此，违反"回指挥中心起飞"规则），起飞后首段航路即朝窗户方向；
- **c)** 测试期间有其他节点/手动遥控向 `/uav/cmd_vel` 发过指令。

5. 穿越前后不停留在竖条内。
