# 图片识别合并方案：LBP+LDA 分类器 × 工程框架

> 日期：2026-10-09
> 合并对象：
> - A 文档《视觉识别方案_0.9准确率》——视觉算法：多尺度 LBP + LDA + 最近类均值（实测 0.90）
> - B 文档《图片识别功能实现框架》——工程框架：话术、话题、航点、判分顺序、接入点（ROS 侧）
> 结论：工程框架照用 B，识别核心用 A。B 的地面/空中模板匹配路线被 A 的实测数据（0.36 vs 0.90）判为死路，但也正是 A 的采集/训练/推理流程需要 B 已有的相机接口、识别停点和 randomize 脚本才能落地。

---

## 1. 合并思路（一句话）

**保留 B 的工程骨架（相机订阅、话术发布、判分顺序、识别停点），把 A 的分类器（LBP+LDA）装进 B 的识别调用点，替换掉模板匹配；采集标签直接复用 randomize 脚本的 `texture_assignment.json`（标签零成本）。**

```
B 工程框架（话题 / 话术 / 航点 / 顺序）
        ↓ 每个识别调用点插入
A 分类器（特征 LBP → 投影 LDA → 最近类均值 → 票差判未识别）
        ↑ 训练数据来源
randomize 脚本（--seed 复现贴图）+ texture_assignment.json（图片→类别 白送）
```

## 3. 总体架构

```
┌─ 环境准备（一次）────────────────────────────────────┐
│ randomize --seed N 打上贴图 → 启动仿真 → 采帧脚本截图   │
│ 标签 = texture_assignment.json 按材质→图片→类别反查     │
└──────────────────────────────────────────────────┘
                      ↓ 每 seed  N 帧 RGB≈110 帧
┌─ 训练（离线，无 ROS）──────────────────────────────────┐
│ patch → 多尺度LBP特征(256维) → LDA降维(40维)             │
│ → 存 (basis, 类中心, 类别表) ≈ 44KB                     │
│ 验证：按 seed 留出，必须分 seed 打印                     │
└──────────────────────────────────────────────────┘
                      ↓ 模型文件
┌─ 部署（minimal_user_node.py 内）─────────────────────┐
│ 地面: 透视矫正(已有) → LBP特征 → LDA投影 → 最近类均值    │
│ 窗户/空中: 中心裁剪 → 同上管道                           │
│ 票差 < 阈值 → 判未识别 → 兜底话术                        │
└──────────────────────────────────────────────────┘
```

依赖保持 B 的零新增：**numpy + OpenCV，无 GPU/torch/sklearn**。识别在回调外做（回调只存帧，保持现状）。

每个 seed 按既有航点停靠，在每个识别点停稳后截帧：

| 场景 | 位置 | 取图方式 | 帧数建议 |

| 窗户 2 点 | 现有窗户识别位 | `/uav/camera/image` 中心裁剪 ROI | 每点 ~15 帧 |

## 5. 环节二：训练（离线脚本，无 ROS）

新增文件 `scripts/train_recognizer.py`。完全照搬 A 文档算法，闭式解、秒级、只依赖 numpy/OpenCV。

### 5.1 特征：多尺度 LBP（256 维）

```python
import cv2, numpy as np

def lbp_codes(gray, radius):
    """8 邻域圆形 LBP，半径 radius。朴素实现即可（采集量小，速度不是瓶颈）。"""
    H, W = gray.shape
    out = np.zeros((H, W), dtype=np.uint8)
    yx = [(dy, dx) for dy in (-radius, 0, radius) for dx in (-radius, 0, radius)
          if not (dy == 0 and dx == 0)]
    for dy, dx, i in [(dy, dx, k) for k, (dy, dx) in enumerate(yx)]:
        y2 = np.clip(np.arange(H)[:, None] + dy, 0, H - 1)
        x2 = np.clip(np.arange(W)[None, :] + dx, 0, W - 1)
        out |= (gray[y2, x2] > gray) << i
    return out

def feature(patch):
    gray = cv2.cvtColor(patch, cv2.COLOR_BGR2GRAY) if patch.ndim == 3 else patch
    gray = cv2.resize(gray, (160, 120))
    total = np.zeros(256)
    for r in (1, 2, 3):                       # A 文档核心：三半径，单尺度对距离敏感
        hist = np.bincount(lbp_codes(gray, r).ravel(), minlength=256)
        total += hist / hist.sum()            # 每个半径先归一化再平均
    vec = total / 3
    return vec / np.linalg.norm(vec)
```

### 5.2 分类：LDA + 最近类均值（40 维）

```python
def train(features_by_class):
    """features_by_class: dict{类别: np.ndarray(N,256)}。返回模型 dict。"""
    X = np.vstack(list(features_by_class.values()))
    y = np.concatenate([[i] * len(v) for i, v in enumerate(features_by_class.values())])
    classes = list(features_by_class.keys())
    mean = X.mean(0); Xc = X - mean
    Sw = Xc.T @ Xc                                   # 类内散度（未按类均值中心化，等价效果）
    for i, v in enumerate(features_by_class.values()):
        mc = v.mean(0) - mean
        Sw -= len(v) * np.outer(mc, mc)
    reg = 1e-3 * np.trace(Sw) / Sw.shape[0]          # A 文档红线：不加正则白化会放大噪声
    Sw += reg * np.eye(Sw.shape[0])
    # 白化 + 类间主方向
    w, V = np.linalg.eigh(Sw);  whitened = V @ np.diag(1 / np.sqrt(np.clip(w, 1e-8, None))) @ V.T
    Sb = sum(len(features_by_class[c]) * np.outer(
        features_by_class[c].mean(0) - mean, features_by_class[c].mean(0) - mean)
        for c in classes)
    Z = whitened @ Sb @ whitened.T
    _, U = np.linalg.eigh(Z)                         # 特征值升序，取尾部 40 个
    basis = whitened.T @ U[:, -40:]
    centers = {c: basis.T @ (features_by_class[c].mean(0) - mean) for c in classes}
    return {"basis": basis, "centers": centers, "classes": classes}

def predict(model, vec):
    p = model["basis"].T @ vec
    dists = {c: np.linalg.norm(p - cv) for c, cv in model["centers"].items()}
    order = sorted(dists.items(), key=lambda kv: kv[1])
    return order[0][0], order[1][1] - order[0][1]    # 类别 + 票差（第一减第二）
```

### 6.1 新增 Recom 模块（节点同级文件 `recognizer.py`）

三处识别（地面/空中/窗户）共用同一管道，差异只在"取 patch 的方式"：

| 场景 | patch 来源 | 
|------|-----------|
| 地面 | `project_board_quad` 透视矫正（已有，**保留**） |
| 空中 | 无人机帧中心裁剪（识别停点已保证目标居中） |
| 窗户 | 无人机帧中心裁剪（识别位已验证图片在画面上半部，取上半中心 ROI） |

```python
class Recognizer:
    def __init__(self, model_path):
        d = np.load(model_path)
        self.basis, self.centers, self.classes = d["basis"], None, d["classes"]
        # centers 是结构化数组，按需还原成 dict
    def classify(self, patch, margin=0.5):
        """返回 (类别|None, 票差)。票差小 → 未识别，match margin 深度。"""
        cls, margin = predict(self.model, feature(patch))
        return (cls if margin >= self.margin_thresh else None), margin
```

## 11. 实跑复盘（2026-10-17）：几何一致性、票差上限与采集污染

本节记录 v1.6 空中停点切换（x=1.00 → 1.30、z=0.80）过程中实测到的三类问题与结论。

### 11.1 一句话

LBP+LDA 模型**绑定成像几何**：识别停点一改（x/z 变），板面在画面里的位置与尺度就变，必须在新几何重采重训；否则票差会退化成"恒等于两中心间距"的**假通过**。

### 11.2 关键机制：2 类 LDA 的票差上限 = 两中心间距

`predict()` 返回的票差 = `|d0 − d1|`（到最近中心与次近中心距离之差），恒 ≥ 0。对 2 类问题，票差的最大值恰好是**两中心间距** `‖c0 − c1‖`：当样本投影落在两个类中心区间之外时，票差被"顶到天花板"。

推论：**"票差 ≥ 0.5" 只是相对判据**。若某点票差**恒等于同一个常数**、且该常数等于中心间距，几乎可以断定模型退化（帧落在训练流形外），而不是高置信度。

实测证据（真值来自 `texture_assignment.json` seed7：AerialTarget1=坍塌废墟、AerialTarget2=救援营地）：

| 模型 | 训练几何 | 运行几何 | 中心间距 | aerial_1 票差 | aerial_2 票差 | 类别判定 |
|------|---------|---------|---------|--------------|--------------|---------|
| 旧模型 | x=1.00 / z=0.80 | x=1.30 / z=0.80 | 0.6143 | 恒 0.6143 | **恒 0.6143** | 两图都判"坍塌废墟" → **aerial_2 判错** |
| 新模型 | x=1.30 / z=0.80 | x=1.30 / z=0.80 | 0.6923 | 0.692（= 上限） | 0.467~0.692 | aerial_1 坍塌废墟 / aerial_2 救援营地，**全对** |

**离线自查法**（不用跑车）：读一帧落盘的 ROI 调试图（`/tmp/aerial_recog_*.png`），对 4 个旋转各算一次票差。若 4 个值**完全相同且等于中心间距**、且两帧 LBP 特征余弦相似度 ≈0.999，即为退化。

### 11.3 教训一：几何变了必须同几何重采重训

- 现象：用旧几何（x=1.00）训练的模型在 x=1.30 运行，类别判错（aerial_2 → 坍塌废墟，真值救援营地）。
- 根因："板面在画面里的位置/尺度"本身就是模型学到的判别信息；跨几何运行时帧落在训练流形之外，LDA 投影被推出两中心区间。
- 做法：改停点 → `collect_dir` 在新停点重采（每点 8 帧，抖动覆盖运行时到位偏差）→ aerial scope 重训 → 训练集自检 + 跑一轮验证类别。

### 11.4 教训二：采集抖动会污染地面模型

- 现象：某轮采集给**所有**停点都加了抖动（地面 ±0.10，包含"板未完全入画"的帧——日志里 ground_1/2/3 出现"板面不在相机视野内（投影失败）"）。用这些帧重训后，地面验证退化：ground_0 0.77→0.47、ground_2 0.77→0.50（跌破阈值 0.5）。
- 结论：**采集抖动的幅度与方向必须与运行时一致**。地面停点在运行时并不加抖动，而采集却灌入大量抖动帧，会稀释"正常几何"的类中心。
- 待办：清理 `data/collected` 中地面点的抖动污染帧后重训，复验 ground_0/ground_2 回到 0.7 以上。

### 11.5 本轮验证结果（2026-10-17）

- **aerial**：aerial_1 → 坍塌废墟 0.69、aerial_2 → 救援营地 0.69，**类别正确**。注意 0.69 ≈ 该几何模型上限（中心间距 0.6923），不能当绝对置信度。
- **window**：window_1 2.19、window_2 2.37（远高于阈值）。
- **ground**：ground_1 0.97、ground_3 0.61、ground_4 1.34 正常；ground_0 0.47、ground_2 0.50 未过阈（受 11.4 抖动污染影响，待清理数据后重训复验）。
- **数据面**：`data/collected` 目前只有 seed07 单一 seed，重训只能做训练集自检，跨 seed 可靠性尚未验证（红线③）。
